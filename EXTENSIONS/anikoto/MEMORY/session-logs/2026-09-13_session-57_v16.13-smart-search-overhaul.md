## Root-cause findings

### Legacy Google engine (the user's reported error)
- **Primary bug (code):** `resolveWithGoogle` used `buildPrompt(query)` — the ENTIRE bracketed
  LLM instruction block — as the literal Google search query. Stealth-browser capture showed
  this hijacks Google into the "AI Mode conversation" UI, whose layout contains NONE of the
  markers the extractor required ("Search Results" / "AI Overview") → extraction always failed.
- **Secondary bug (timing):** AI Mode streams its answer AFTER onPageFinished; the old fetcher
  grabbed the first text (≥200 chars = "done") → often captured a pre-answer shell
  ("AI Mode response is ready" / "Transcribing...").
- **Tertiary (test-fix):** during validation, two data-dependent bugs were caught and fixed
  before shipping: (a) "See your Search history" was wrongly used as a footer-cut marker (it's
  sidebar UI — the cut destroyed the whole answer), (b) the 40%-window echo/junk filter shrank
  when text got truncated and let junk through; title-like lines must survive echo filtering so
  exact-title answers aren't eaten; single-word quoted titles ("Dandadan") must be accepted.

### Gemini engine hardening
- Thinking-enabled models can burn the old 512-token budget on reasoning → empty text.
  Now: `thinkingConfig.thinkingBudget=0` first, auto-retry without it if the model 400s on
  "thinking"; maxOutputTokens 2048; `thought:true` parts filtered; finishReason logged.
- Model IDs verified via web docs: `gemini-3.8-flash`, `gemini-3.5-flash-lite` (default),
  `gemini-3.1-flash-lite`.
- Sandbox could NOT live-call Gemini: egress is Hong Kong → 400 FAILED_PRECONDITION "User
  location is not supported". Key detail: that error shape proves the user's key AUTHENTICATES
  (location check happens after auth).
- Prompt improved + LLM-tested (z-ai skill as proxy): added exact-title anchoring; fixed a
  "frieren"→"My Hero Academia" hallucination; stable on re-runs.
