   - `PUT /contents/.write-perm-test.txt` → **403 "Resource not accessible by personal access token"**

     fine-grained-token quirk)

   Contents: Read and write**. Everything else is DONE; publication is ONE script run once a
   writable token arrives: `/home/z/anikoto-workflow/dist-publish-v16.13.sh <apk> <token>` (sandbox-only).
3. **Index `apk` field fix (real "other issue" found this session)**: the user's in-app repo URL is
   `https://raw.githubusercontent.com/Confused-Creature-180/aniyomi-extensions/repo/index.min.json`
   (docs/add-repo.html). Aniyomi normalizes that to base `…/repo` and resolves the index's `apk`
   field as a repo-relative path (keiyoushi convention, e.g. `"all/mangadex.apk"`). The dist index
   has carried a BARE filename (`"aniyomi-en.anikoto180-v16.12-release.apk"`) while APKs live under
   `apk/` → `<repoBase>/<apk>` = branch root = **404 — in-app install/update silently broken since
   v16.10** (users could only sideload from the download page, whose links point at `repo/apk/…` and
   work). v16.13's index uses `"apk": "apk/aniyomi-en.anikoto180-v16.13-release.apk"` → in-app
   updates work again. No old files are touched (append-only).
